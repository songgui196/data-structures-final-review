# 算法与解题模式

## 数据、数据元素、数据项与数据对象（第1章）

辨析这些术语，应先确定题目把什么作为一个完整的处理对象，再划分整体和字段。数据是能够输入计算机并由程序处理的符号的总称；数据元素是通常作为整体考虑和处理的基本单位；数据项是组成元素且具有独立含义的不可再分单位；数据对象则是性质相同的数据元素的集合。这里的“不可再分”依赖当前问题的描述层次，并不等于无法拆成字符或二进制位。

1. 圈出题目明确的处理对象，例如“一条完整借阅记录”，据此识别数据元素。
2. 列举组成该记录的独立字段，区分某个字段与整个记录。
3. 检查集合中的成员是否具有相同性质，再判断其是否构成题目中的数据对象。
4. 作答时同时写清应用场景，避免脱离上下文断言某个现实实体永远属于一种术语。

## 逻辑结构与存储结构（第1章）

数据结构不仅包含数据元素，还包含元素之间的特定关系。逻辑结构面向问题，描述元素之间是什么关系，与计算机中的实际地址无关；存储结构面向实现，说明如何在存储器中表示元素和关系。集合、线性、树和图是本节的四类基本逻辑结构，顺序与链式是本节介绍的两种基本存储结构。判题时要先判断题干在讨论关系还是表示方法，不能用“物理上相邻”代替“逻辑上相邻”。

1. 先抽取关系：是否只有成员关系，还是有先后、层级或任意多重联系。
2. 将关系分类为集合、线性、树或图，暂时不讨论数组和指针。
3. 再分析如何落地：靠连续位置表达联系，还是靠指针连接结点。
4. 遇到同一线性表的数组版和链表版，保留相同逻辑关系，分别判断其存储结构。

## 数据类型、抽象数据类型与操作契约（第1章）

数据类型由一组性质相同的值及定义在这些值上的操作构成。抽象数据类型ADT进一步从应用问题出发，用数据对象、数据关系和基本操作描述一个数学模型。它强调对外提供什么能力以及使用操作的条件，不把某一种数组布局、结点地址或具体算法写成抽象模型不可更换的组成部分。判断ADT是否相同时，应比较操作含义和可观察结果，而不是只比较内部变量名。

1. 识别ADT描述中的对象范围，例如所有有限整数序列。
2. 明确对象内部的关系，例如序列中的先后关系。
3. 对每个操作写出输入、初始条件和正常结果，区分返回值与对象变化。
4. 更换数组或链表实现时，检查外部操作语义能否保持，若保持则不因实现变化否定同一抽象模型。

## 算法的五个特性与评价标准（第1章）

算法是为解决某一类问题而规定的有限操作序列。教材从有穷性、确定性、可行性、输入和输出五方面说明算法特征：它必须在有限步骤内结束，每一步含义明确，操作能够通过有限的基本操作实现，可有零个或多个输入，但至少有一个输出。五个特性用于判断一个过程能否称为算法；正确性、可读性、健壮性和效率等则用于评价算法质量，两个层面不能互相替代。

1. 先明确输入范围和目标输出，避免只看一段缺乏上下文的语句。
2. 寻找终止条件与推进量，判断所有合法输入下是否会结束。
3. 核对每步是否明确可执行，区分数学上的愿望与可实施的操作。
4. 在能正确完成任务的前提下比较时间、空间和可维护性，不把某个指标当作唯一标准。

## 语句频度、时间复杂度与辅助空间（第1章）

复杂度分析关注资源消耗随问题规模n增长的趋势，不等于测量某台机器运行了多少秒。时间分析先确定基本操作，再求其执行次数；顺序执行的部分相加，嵌套循环则根据真实上下界求和，不能见到两层循环就直接判为平方阶。渐近表示通常忽略常数因子和低阶项。教材常用O记号表达数量级，做选择题时应取最贴切的紧数量级，不能利用O的上界含义选一个过宽的阶。

1. 定义n的含义和输入前提，确定要数的基本操作。
2. 写出循环体精确次数或求和式，处理内层依赖外层的上下界。
3. 化简并保留主导增长项，写明最好、最坏或平均假设。
4. 清点额外变量、数组及递归栈，另给空间结论，避免把时间与空间混为一谈。

## 顺序表表示、位序与地址计算（第2章）

线性表是具有相同特性的数据元素的有限序列，长度可以为零；非空线性表的元素具有先后关系。顺序表利用一段连续空间存放线性表。教材中的逻辑位序从1开始，而C数组下标从0开始，因此第i个元素存于elem[i−1]。计算地址时应先统一基地址所对应的元素，再乘每个元素占用的存储单元数。顺序访问与随机存取不是同一个概念，随机存取说明按给定位序定位可为常数时间。

1. 写出B对应的是a1还是其他下标处的元素，并记录单位。
2. 将目标位序转换为相对于基元素的偏移个数。
3. 用偏移个数乘单个元素大小，再加基地址。
4. 检查位序是否落在有效元素范围；空表没有可取的第一个数据元素。

## 顺序表取值与按值查找（第2章）

顺序表取值与按值查找回答不同问题。给定位序取值，可通过elem[i−1]直接取得元素，时间为O(1)；给定一个值寻找位置，在未排序的表中通常需要逐个比较，最坏时间为O(n)。本节遵循教材算法2.3的返回约定：从表头向后查找，成功返回第一个相等元素的1起始位序，失败返回0。这样位序1和失败0不会冲突，也便于分析重复值与空表。

1. 先确认输入是位序还是目标值，避免把取值复杂度套给查找。
2. 从下标0比较到length−1，首次相等返回下标加1。
3. 循环结束仍未命中，返回0；空表循环不执行也返回0。
4. 按命中位序或失败情况统计比较次数，再在明确的概率模型下求平均。

## 顺序表插入、删除与移动次数（第2章）

在长度为n的顺序表第i个位序插入，含义是在原第i个元素之前放入新值；允许1≤i≤n+1，且必须留有容量。由于逻辑顺序要保持，插入时应从后向前把原元素整体右移，避免覆盖尚未搬走的数据。删除第i个元素则要求1≤i≤n，先保存被删值，再把其后的元素从前向后左移。两种操作均在成功后恰好修改一次长度，非法请求应保持表及输出参数不变。

1. 先核对当前长度、容量和位序，不合法立即失败且不修改状态。
2. 插入采用从后向前右移，删除采用从前向后左移，写明首末下标。
3. 写入新值或保存被删值，再在成功路径更新length。
4. 用操作前的长度计算本次移动次数；连续多次操作必须先更新长度再算下一步。

## 带头结点单链表与头插法（第2章）

本知识点统一采用带头结点的非循环单链表：L指向头结点，头结点不作为有效数据元素计数，首元结点由L->next指向，尾结点的next为NULL。头插法每次把新结点接在头结点之后，故按某顺序读入数据后，最终数据次序与读入次序相反。头插的核心不在申请结点，而在正确保存原首元链，再让头结点指向新结点；交换这两条接链语句可能制造自环并丢失原链。

1. 建立或确认有效头结点，并令空表L->next=NULL。
2. 申请新结点p、检查分配结果，再写入数据域。
3. 先执行p->next=L->next保存原首元链，再执行L->next=p完成接入。
4. 处理下一个输入；模拟时每步都从L->next重画实际逻辑顺序。

## 尾插法、前驱操作与存储取舍（第2章）

尾插法用尾指针r保持最后一个结点的位置，每读入一个新值，就把新结点接在r之后并更新r。带头结点的空表将r初始化为L，可使第一个数据结点与后续结点采用同样的接链步骤。尾插保留输入顺序；若每插一个结点都从头重新寻找表尾，整个建表会从O(n)退化到O(n²)。链表插删是否高效，也取决于是否已经得到所需前驱，不能只看最终改了几条指针。

1. 建立头结点令L->next=NULL，并置r=L。
2. 为输入值建立p，先令p->next=NULL，保证其可作为新尾结点。
3. 依次执行r->next=p、r=p，维持尾指针不变式。
4. 建表失败时释放本次已建结点；处理删除时先保存后继再释放原结点，并检查是否另有持久尾指针需更新。

## 栈与队列的逻辑规则及操作序列（第3章）

栈与队列都是操作位置受到限制的线性表。栈只在同一端进行插入和删除，后进入且尚未删除的元素先出，称为LIFO；队列在队尾插入、队头删除，先进入且尚未删除的元素先出，称为FIFO。操作序列题应逐步模拟当前状态，不能只把全部输入简单逆序或原序抄成输出，因为入和出可以交错。题目还必须约定空时删除、满时插入如何处理；未说明容量时不要自行添加溢出限制。

1. 先写明初态、栈底到栈顶或队头到队尾的记录方向，以及失败操作的约定。
2. 每次插入先检查容量，再加入对应一端；每次删除先检查是否为空。
3. 把每次成功删除的值立即记入输出序列，失败则保持题定状态。
4. 最终分别给出输出、剩余内容和是否发生非法请求，不能只报最后一个值。

## 顺序栈的base、top与基本操作（第3章）

采用教材的指针式顺序栈，base指向已分配存储区的栈底，top始终指向下一处可压入位置。初始化后top=base；非空时真正的栈顶元素位于top−1。因而空栈条件是top==base，而不是取top指向的元素判断。压入时先写*top再递增top；弹出时先递减top再读值。base为NULL表示尚无有效栈存储，不能据此直接作已初始化空栈的指针差运算。

1. 确认栈已初始化，base与top属于同一有效分配区，且容量已知。
2. 压入先判top−base==stacksize，再写当前top并递增。
3. 弹出先判top==base，再把top前移一个元素并读取。
4. 取顶只读top−1，不移动指针；每一步用top−base检查当前长度。

## 预留一个空位的循环队列（第3章）

固定采用数组容量M、下标0至M−1、预留一个空位的循环队列，要求M≥2。front指向当前队头元素，rear指向下一次入队的写入位置；初态front=rear=0。入队成功后rear循环前进，出队成功后front循环前进。front==rear表示空；(rear+1)%M==front表示满，最多装M−1个元素。预留的是判别空间，不是永远禁用数组的最后一个下标，随着回绕任何位置都可能成为当前空位。

1. 先写容量M、预留空位约定与初始front、rear，核对下标范围。
2. 每次入队按满条件判断，成功时先存值再令rear=(rear+1)%M。
3. 每次出队按空条件判断，成功时先取值再令front=(front+1)%M。
4. 用(rear−front+M)%M核对长度，并从front逐个回绕列出有效元素。

## 无头结点链栈的压入与弹出（第3章）

这里采用教材不带头结点的链栈，栈顶指针S直接指向第一个数据结点。空栈用S==NULL表示，不能把带头结点单链表的L->next==NULL原样搬来。压入一个新结点时，先让它指向原S，再更新S；弹出时保存原栈顶结点及其后继，移动S后释放旧结点。两种操作都只在链首进行，不需要沿链查找尾部，逻辑上仍严格遵循后进先出。

1. 初始化实际栈顶变量为NULL，并将其地址交给需要改顶的函数。
2. 压入先申请p，失败则返回；成功后写数据、p->next=*S、*S=p。
3. 弹出先检查*S非空，保存p=*S及p->data，再令*S=p->next。
4. 最后free(p)，保证不在释放后再读p->next；空栈失败不改输出。

## 带头结点链队及最后一个元素的删除（第3章）

本节采用带头结点的链队。front始终指向头结点，真正的队头数据结点是front->next；rear指向最后一个数据结点，空队时rear也指向头结点。入队把新结点接在rear之后再更新rear，出队删除front后面的首个数据结点。由于头结点本身始终保留，front不必沿数据链移动；删去最后一个数据结点时必须把rear复位到front，避免留下指向已释放结点的悬空指针。

1. 确认队列已初始化，front有效且rear指向当前尾结点或空队头结点。
2. 入队前申请新结点，成功后接到rear并更新rear，失败不改队列。
3. 出队先判front==rear，非空才取得front->next并保存数据。
4. 先接回后继，若删的是尾结点则rear=front，再释放旧队头；用下一次入队检验空态是否完整。

## BF：逐起点比较与失配回退（第4章）

BF 从指定起点逐一尝试主串的候选子串。每一趟都将模式第一个字符对准一个新起点，逐字符比较；失败时既回退主串指针，也重置模式指针。适合短串、一次性查找或用作其他匹配算法的正确性参照。以下仅处理非空模式与合法起点，返回首次匹配的1-based位置，失败返回0。

1. 先确认字符存于 ch[1..length]，T 非空且 1≤pos≤S.length，初始化 i=pos、j=1。
2. 只在 i≤n 且 j≤m 时比较：相等则 i、j 同增，否则按旧 j 回退主串并将 j 置1。
3. 循环结束先检验 j>m；若成立返回 i-m，否则返回0。成功位置是模式首字符对应位置。

## KMP：主串不回退的匹配过程（第4章）

KMP 利用模式中已经确认相等的前后缀，在失配时移动模式的对齐位置，主串比较指针 i 不减小。它并非保证每个主串字符只比较一次，而是避免重新从主串更早位置开始匹配。适合模式存在较多重复部分、主串较长或需要单向读取的情况；同一模式可复用其辅助表。

1. 根据明确的1-based约定先求 next，初始化 i=pos、j=1。
2. j=0 时只移动两个指针，不做字符比较；否则字符相等则同增，失配则仅令 j=next[j]。
3. 按 j>m 判断成功并返回 i-m；记录比较次数时只统计实际的字符相等性判断。

## next：失配位置前缀的最长相等真前后缀（第4章）

本章 next[j] 表示在模式第 j 个字符失配后，下一次应比较的模式位置，不是前后缀的长度本身。采用教材1-based约定 next[1]=0；j≥2时查看的是 T[1..j-1]，求其最长相等真前缀与真后缀长度，再加1。若没有非空相等真前后缀，则长度记0，所以 next[j]=1。

1. 手算时列 j、T[j]、T[1..j-1]、最长真边界长度l；第1项写0，其余写l+1。
2. 线性算法从 i=1、j=0 开始；若 j=0 或 T[i]=T[j]，先同增 i、j，再令next[i]=j。
3. 否则令 j=next[j] 并保留 i；循环条件 i<m，避免生成本接口不需要的 m+1 项。

## nextval：跳过必然再次失配的候选（第4章）

nextval 在普通 next 的基础上压缩一段必然失败的回退链。已经知道 S[i]≠T[j]，如果回退候选 k=next[j] 满足 T[k]=T[j]，再拿 S[i] 与 T[k] 比较一定失败，可以继续跳转。它改变的是辅助表中的回退目标，KMP匹配的主循环和首次匹配结果均不改变。

1. 先算普通next，以方便用定义核对；再按j从2到m依次比较T[j]与T[next[j]]。
2. 字符不同保留next[j]；相同则取已求出的nextval[next[j]]，必要时效果等同于跳过整条重复字符链。
3. 用重复字符模式在相同主串上分别运行两种辅助表，核对匹配位置相同并只统计字符比较。

## 二维数组：行优先、列优先与非零下界地址（第4章）

二维数组顺序存储需要把二维下标映射成一维偏移。按行优先先存完一整行再存下一行；按列优先先存完一整列再存下一列。公式适用于每个元素等长、连续、未压缩的存储；须先说明基址对应哪个元素，以及每个元素占多少个地址单位。

1. 写出合法下标范围并求r、c，明确B对应左上角元素而非任意已知元素。
2. 按存储顺序先数完整行或完整列，再加所在行或列内的剩余元素数。
3. 用元素偏移乘w后加B；用首元素偏移0、末元素偏移rc-1检查公式。

## 广义表：原子、子表、表头与表尾（第4章）

广义表把线性表的元素推广为原子或子表，定义本身具有递归性。判断题先区分当前最外层的元素与嵌套内部元素，再区分某对象是原子还是表。教材允许子表共享与递归表；本节长度和操作演算选用有限、无循环的具体表，不把未点名的其他内容判定为排除。

1. 从最外层括号内按逗号分项，子表内部逗号不分割上层元素。
2. 取Head时返回第一个元素本身；取Tail时删去第一项并为剩余项保留一层表结构。
3. 连续运算前检查操作对象：必须是非空表，不能对原子或空表继续套用本接口。

## 树的基本术语与性质（第5章）

树是n个结点的有限集合，非空时有且仅有一个根，其余结点划分为互不相交的子树。结点的度是孩子数，树的度是各结点度的最大值；叶结点度为0。层次从根的第一层开始，树的深度是最大层次。树中除根外每个结点有一个双亲，所以边数为n−1。非空二叉树还满足叶结点数n0等于度为2的结点数n2加1。答题时先确认一般树或二叉树，再使用对应性质；满二叉树、完全二叉树、平衡二叉树不可混为一谈。

1. 标出根并核对每个非根结点是否仅有一个双亲。
2. 需要求边数时用非根结点数n−1。
3. 二叉树计数时分别统计度为0、1、2的结点。

## 二叉树遍历与建树（第5章）

前序是根—左—右，中序是左—根—右，后序是左—右—根，层序使用队列按层访问。前三种深度遍历递归调用完全相同，区别仅在访问根的位置。结点值互异时，前序加中序或后序加中序可唯一确定二叉树；仅给前序和后序通常无法判断单孩子在左还是右。重建时先在中序区间定位根，再按左子树结点数切分另一个序列。题目须交代遍历序列和结点互异等条件；实现固定闭区间，空区间返回空树。

1. 先识别已知序列中的根结点。
2. 在中序序列里找到根，划分左右子树。
3. 按左右子树长度划分其他遍历序列。
4. 递归处理左右区间，遇空区间返回。

## 哈夫曼树、编码与WPL（第5章）

哈夫曼树通过反复合并当前森林中权值最小的两棵树构造；新树权值为两者之和，再放回候选集合。n个非零权叶结点最终形成n−1个内部结点。约定左分支编码0、右分支编码1时，每个叶的根到叶路径组成字符码，任一码都不是另一码的前缀。带权路径长度WPL等于叶权值乘其深度后求和；交换左右孩子不改变WPL。手算须每轮从整个候选森林重新挑两棵最小树；并列最小值可能给出不同树形，但总权长度仍可最优。

1. 把所有叶权作为候选森林。
2. 每轮选两个最小者合并并记录新权值。
3. 直到剩余一棵树。
4. 按约定左右分支编码，计算每个叶的深度和WPL。

## 树与二叉树的存储表示（第5章）

二叉链表结点保存数据、左右孩子指针；空孩子用空指针表示。顺序存储适合完全二叉树，但稀疏树会浪费较多数组单元；数组孩子下标关系须明确采用0还是1起始。孩子兄弟表示可用“第一个孩子”和“下一个兄弟”两个指针表示一般树。线索二叉树利用空指针记录遍历前驱或后继，需以标志域区分线索与孩子链接。选择存储结构时结合树的稠密度和基本操作需求；题目若未给空标记和根下标，不能自行假定序列化格式。

1. 确认需表示一般树还是二叉树。
2. 若需频繁定位孩子，按结点关系选择链接表示。
3. 使用线索时读取标志域并遵循对应遍历次序。

## 图的术语与存储（第6章）

图G由顶点集V和边集E组成。有向边为有序对，无向边为无序对。邻接矩阵用n×n数组记录邻接关系或边权，查询直接但空间O(n²)；邻接表按顶点保存其邻边，适合稀疏图。无向图每条边在两个端点的邻接表中各出现一次；有向图只记录弧的起点所发出的边。带权图的路径长度为边权之和，无权图则按边数计。算法前先确定有向性、边权以及不存在的边标记，避免把∞当成可相加的普通值。

1. 确定顶点编号和边的方向。
2. 按题目约定建立矩阵或邻接表。
3. 确认无边标记和对角线取值。

## DFS与BFS遍历（第6章）

深度优先搜索沿未访问邻点递归深入，不能继续时回溯；广度优先搜索用队列先访问离起点较近的顶点。每次首次发现顶点就立即标记，再压栈、递归或入队，确保不会反复处理同一顶点。若图不连通，从单一起点搜索无法覆盖全图，需外层循环对尚未访问的顶点再次启动。遍历次序受邻接表顺序影响，题面应给出顺序，否则可存在多个合法答案。邻接表表示下两者复杂度均为O(|V|+|E|)。

1. 清空visited标记。
2. 标记起点后开始搜索。
3. DFS递归邻点，BFS则出队后扫描邻点。
4. 非连通图继续检查未访问顶点。

## Prim与Kruskal最小生成树（第6章）

连通无向带权图的最小生成树覆盖所有顶点、无回路并含|V|−1条边。Prim从指定顶点开始，每轮选连接当前树内外顶点的最小权边；Kruskal将边按权排序，仅接纳连接不同连通分量的边。Prim扩展单个连通树，Kruskal不断合并森林。非连通图不能有覆盖全图的生成树。多条等权边可能产生不同但权值相同的MST；构造题需指定并列规则，或说明任何合法最小树均可。检查解时同时核对连通、无环、边数和总权。

1. Prim：固定起点，维护树内到树外的最轻边。
2. Kruskal：排序全体边，逐条检查是否成环。
3. 达到|V|−1条边后结束。
4. 复核覆盖全体顶点且总权最小。

## Dijkstra与Floyd最短路径（第6章）

Dijkstra求非负权图单源最短路径：每轮从未确定顶点选当前dist最小者，再松弛其出边；负边可能让已确定距离再次变小，破坏贪心正确性。Floyd求任意两点最短路，依次将顶点k作为可选中间点，检查dist[i][k]+dist[k][j]是否改进dist[i][j]。无边初始化为∞，dist[i][i]=0。若需要输出具体路径，需另存前驱或next矩阵；仅有距离矩阵不够恢复路线。实现时保护无穷值，避免把∞参与加法后产生伪更新。

1. 写明起点或初始化全部点对距离。
2. Dijkstra选择未确定的最小dist并松弛出边。
3. Floyd按k、i、j三层循环更新。
4. 更新路径时同步维护前驱信息。

## 顺序、折半与分块查找（第7章）

顺序查找逐项比较，适用于无序表，最坏O(n)。折半查找要求表有序且支持随机访问；在闭区间[low,high]内比较mid。若A[mid]<key，则low=mid+1；若更大，high=mid−1；若相等则命中。每轮区间约缩小一半，时间O(log n)。分块查找块间索引有序、块内再顺序查找，折中动态更新与搜索速度。重复值题须规定返回任一匹配位置还是左右边界；代码要防溢出式中点计算与越界。

1. 初始化闭区间[0,n−1]。
2. 计算中点并比较。
3. 保留包含目标的半区且排除已比较中点。
4. 区间空时报告失败。

## 二叉排序树查找与构造（第7章）

二叉排序树满足左子树关键字小于根，右子树关键字大于根，且左右子树也满足该性质。查找按比较方向逐层下降；插入新关键字时走同一路径至空链接并建立新叶。中序遍历得到递增序列。树的形状受插入顺序影响，接近平衡时查找O(log n)，单支树最坏O(n)。若有重复值，需预先定义计数或放置方向；本库建树题使用互异关键字。构造过程应逐个展示比较路径，而非只画最终树。

1. 首个关键字建立根。
2. 逐个与当前结点比较。
3. 较小向左、较大向右直到空链接。
4. 按中序核验全局顺序。

## 散列表与冲突处理（第7章）

散列函数将关键字映射到有限表地址，不同关键字可能映射到同一位置，称为冲突。开放定址在表内探测后继位置；链地址法在一个地址维护冲突链。线性探测从初始地址依次检查并按表长循环。装填因子α=n/m表示记录数与表长比，开放定址中装填越高，冲突通常越多。查找遇空槽判失败的前提是插入和删除正确维护空、占用、删除标记状态。作表时应同时写初始散列地址与探测后最终落点。

1. 逐个计算H(key)。
2. 若已占用，按指定探测策略继续。
3. 记录最终落点并更新占用状态。

## 平衡树与多路查找概览（第7章）

平衡二叉树在二叉排序树基础上限制子树高度差，并通过旋转保持对数高度；红黑树用颜色约束实现较宽松平衡。B树每个结点可含多个关键字和多棵子树，适合外存多路索引、降低磁盘访问次数。不同查找结构通过额外的存储或维护代价换取较稳定的查找路径。答辨析题时分清每种结构的组织方式与适用场景，不将二叉排序树平均性能和最坏性能混为一谈。

1. 确定查找结构与存储层次。
2. 说明该结构维护的平衡或排序性质。
3. 据树高或磁盘访问分析性能。

## 排序性质与复杂度（第8章）

稳定性指关键字相同记录排序后相对次序不变；它与是否原地排序、是否适合链表是不同属性。直接插入和冒泡的常用版本稳定；希尔、快速、堆通常不稳定；归并在相等时先取左段可保持稳定。快速排序平均O(nlog n)、最坏O(n²)；归并和堆最坏O(nlog n)。归并通常需O(n)辅助空间，堆排序可O(1)额外空间。复杂度表要结合具体算法版本和初始序列，不能只因一组有序输入就给一般最坏界。

1. 逐一比较时间、辅助空间、稳定性。
2. 指出复杂度属于最好、平均还是最坏。
3. 检查算法适用的存储结构与数据条件。

## 直接插入与希尔排序（第8章）

直接插入每次把当前记录插入前面已排序前缀，较大记录向右移动；稳定，近乎有序时最好O(n)，一般与最坏O(n²)。希尔排序使用递减增量把记录分组并做组内插入，最后增量1完成全体直接插入。某趟之后，只保证每个增量子序列各自有序，不保证整个序列已全局有序。希尔排序通常不稳定，时间界依赖增量序列。做希尔手算时应明确增量、分组、组内处理顺序；增量没给时，不应给唯一中间序列。

1. 将第一个元素视作有序区。
2. 保存当前待插关键字。
3. 较大前驱依次右移。
4. 放入空位；希尔每个增量组独立执行此步骤。

## 冒泡排序与快速排序（第8章）

冒泡排序反复比较相邻记录并交换逆序对；升序的常见从左向右版本会把当前未排序区最大值送到右端，一趟无交换可提前结束。快速排序选择枢轴，按分区约定将区间划成左右子区后递归；平均O(nlog n)，最坏O(n²)，常见版本不稳定。枢轴选取、扫描方向和等值处理都会影响中间结果。这里的 Lomuto 版本用末元素作枢轴，从左向右扫描，严格小于枢轴的元素进入左区。作答必须照题目指定的代码移动下标；缺少明确版本时只描述性质，不把单一划分轨迹当成通用答案。

1. 确定升序/降序和当前未排序范围。
2. 按题定版本选择枢轴和扫描方向。
3. 逐次记录比较、交换与指针移动。
4. 分区完成后递归处理两侧。

## 堆排序与归并排序（第8章）

堆排序先建堆，再将堆顶与未排序区末端交换并逐步缩小堆区，随后向下筛选恢复堆性质；最坏O(nlog n)、原地但不稳定。归并排序反复把相邻有序段合并，平均和最坏O(nlog n)，通常需O(n)辅助空间；相等时优先取左段可保持稳定。堆的孩子下标要依据0/1起始公式统一；归并的左右输入区间与输出临时区间边界必须一致。两者每趟操作逻辑不同，不要用“取当前最小值”概括替代实际调整/归并。

1. 堆：建初堆，交换堆顶与末端，缩小范围并筛选。
2. 归并：逐对比较两个有序段头部。
3. 处理剩余尾段并写入辅助区。
4. 按趟次扩大合并段长。
