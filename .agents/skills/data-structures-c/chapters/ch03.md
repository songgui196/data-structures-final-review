## 栈与队列的逻辑规则及操作序列

**复习层级：** focus；**依据：** explicit。

栈与队列都是操作位置受到限制的线性表。栈只在同一端进行插入和删除，后进入且尚未删除的元素先出，称为LIFO；队列在队尾插入、队头删除，先进入且尚未删除的元素先出，称为FIFO。操作序列题应逐步模拟当前状态，不能只把全部输入简单逆序或原序抄成输出，因为入和出可以交错。题目还必须约定空时删除、满时插入如何处理；未说明容量时不要自行添加溢出限制。

**核心概念**

- **栈的合法输出：**固定输入次序时，可以在任意允许的时刻出栈，但只能取当前栈顶。判断目标输出时，为输出一个尚未入栈的元素，可依次压入到它；若目标已经被别的未弹元素压住，就不能直接取出。
- **队列的保序性质：**只用普通队尾入、队头出且不丢失元素时，成功出队的元素次序保持成功入队的相对次序；这与队列采用数组还是链表无关。
- **表示与规则分层：**LIFO和FIFO是逻辑规则；空判定、指针名称及容量限制属于具体表示。指针重合的含义必须先看顺序栈、循环队列或带头结点链队的定义。

**操作步骤**

1. 先写明初态、栈底到栈顶或队头到队尾的记录方向，以及失败操作的约定。
2. 每次插入先检查容量，再加入对应一端；每次删除先检查是否为空。
3. 把每次成功删除的值立即记入输出序列，失败则保持题定状态。
4. 最终分别给出输出、剩余内容和是否发生非法请求，不能只报最后一个值。

**易错点**

- 栈的整个输出不一定是输入的完全逆序，交错出栈可形成多种合法输出。
- 普通队列不能跳过队头取出后面的元素；取队头与删除队头也不是同一操作。
- 对顺序栈应说栈顶与栈底，不能把top、base称作队列头尾指针。

### 例题：同一操作节奏比较LIFO与FIFO

**题目：**容量足够，初态为空。依次加入6、加入2、移出一次、加入9、移出两次。分别按栈和队列规则求输出与最终状态。

1. 栈：加入6、2后栈底到顶为(6,2)，第一次移出2，余(6)。
2. 再入9成为(6,9)，后两次依次移出9、6。
3. 队列：加入6、2后队头到尾为(6,2)，第一次移出6，余(2)。
4. 再入9成为(2,9)，后两次依次移出2、9；两者最终都为空。

**结论：**栈输出(2,9,6)，队列输出(6,2,9)，最终均为空，全部操作合法。

**教材来源：**3.1.1 栈的定义和特点；3.1.2 队列的定义和特点；印刷页62–63（PDF第74–75页）。

**范围依据：**范围依据第三章明确强调后进先出、先进先出以及入栈出栈、入队出队；用教材核定具体表示，不将训练类型当作命题保证。

## 顺序栈的base、top与基本操作

**复习层级：** focus；**依据：** explicit。

采用教材的指针式顺序栈，base指向已分配存储区的栈底，top始终指向下一处可压入位置。初始化后top=base；非空时真正的栈顶元素位于top−1。因而空栈条件是top==base，而不是取top指向的元素判断。压入时先写*top再递增top；弹出时先递减top再读值。base为NULL表示尚无有效栈存储，不能据此直接作已初始化空栈的指针差运算。

**核心概念**

- **长度与容量：**在同一已分配数组范围内，top−base表示元素个数，单位是元素而非字节。容量为stacksize时，可使用全部stacksize个单元，不需要像本章循环队列那样额外预留一个空位。
- **压入与弹出：**满时压入失败且不写数组；空时弹出失败且不读栈顶。成功压入可写*top++=e，成功弹出可写e=*--top，但须分清后置与前置的时机。
- **只读栈顶：**取栈顶访问*(top−1)，不改变top；弹出会改变top。输出参数必须指向可写且不与栈内部冲突的对象，失败路径不应产生伪结果。

**操作步骤**

1. 确认栈已初始化，base与top属于同一有效分配区，且容量已知。
2. 压入先判top−base==stacksize，再写当前top并递增。
3. 弹出先判top==base，再把top前移一个元素并读取。
4. 取顶只读top−1，不移动指针；每一步用top−base检查当前长度。

**公式与适用条件**

| 项目 | 公式或结论 | 适用条件 |
|---|---|---|
| 空栈 | S.top==S.base | 有效初始化的教材指针式顺序栈。 |
| 长度与满栈 | len=S.top−S.base；len==S.stacksize时满 | 指针位于同一栈数组内或其尾后一位。 |

**易错点**

- top是下一空位，直接读*top并不是取栈顶，满栈时还会越界。
- *top--先取旧top再减，与正确的*--top不等价。
- 这里没有front或rear；不同实现用top=-1判空也可能正确，但不适用于本表示。

### 例题：容量边界下的压入与弹出

**题目：**容量3，初态top=base。依次Push(10)、Push(20)、Pop、Push(30)、Push(40)、Push(50)、Pop，求两次弹出值及最终状态，失败压入保持栈不变。

1. 压入10、20后长度2，首次Pop先减top，得到20，余(10)。
2. 再入30、40后长度3，栈底到顶(10,30,40)，top=base+3。
3. 入50时已满，失败且长度仍为3。
4. 末次Pop得到40，余(10,30)，top=base+2。

**结论：**弹出20、40；Push(50)失败；最终(10,30)，长度2。

**教材来源：**3.3.2 顺序栈的表示和实现，算法3.1—3.4；印刷页66–68（PDF第78–80页）。

**范围依据：**范围依据第三章明确强调后进先出、先进先出以及入栈出栈、入队出队；用教材核定具体表示，不将训练类型当作命题保证。

### 重构类C示例（C指针接口，非教材源码逐字转写）

```c
typedef struct { int *base, *top; int stacksize; } SqStack;
/* S已初始化，base/top同属一个有效分配区，容量为stacksize。 */
int Push(SqStack *S, int e) {
    if (!S) return 0;
    if (S->top - S->base == S->stacksize) return 0;
    *S->top++ = e;
    return 1;
}
int Pop(SqStack *S, int *out) {
    if (!S || !out || S->top == S->base) return 0;
    *out = *--S->top;
    return 1;
}
int Peek(const SqStack *S, int *out) {
    if (!S || !out || S->top == S->base) return 0;
    *out = *(S->top - 1);
    return 1;
}
```

- 结构与指针含义遵循教材；用C指针参数和int元素替代教材引用参数、SElemType。
- 前提：stacksize>0，base指向相应容量数组，base≤top≤base+stacksize；不允许损坏表示。
- Pop与Peek的out为独立可写对象；代码为重构示例，未声称经本机编译运行。

## 预留一个空位的循环队列

**复习层级：** focus；**依据：** explicit。

固定采用数组容量M、下标0至M−1、预留一个空位的循环队列，要求M≥2。front指向当前队头元素，rear指向下一次入队的写入位置；初态front=rear=0。入队成功后rear循环前进，出队成功后front循环前进。front==rear表示空；(rear+1)%M==front表示满，最多装M−1个元素。预留的是判别空间，不是永远禁用数组的最后一个下标，随着回绕任何位置都可能成为当前空位。

**核心概念**

- **入队与出队顺序：**入队先判满，再写data[rear]，最后更新rear；出队先判空，再保存data[front]，最后更新front。失败操作不改指针、不写输出，取队头则只读不移动front。
- **回绕与逻辑顺序：**rear数值小于front并不表示空；队列逻辑顺序应从front沿模M逐一枚举到rear之前。删除不会要求整体搬移数组，旧值残留也不算有效元素。
- **方案的适用边界：**若使用额外计数器或满空标志，可以设计装满M个元素的另一方案；那时相同指针位置可能需要辅助状态才能判满，不能直接套用本节结论。

**操作步骤**

1. 先写容量M、预留空位约定与初始front、rear，核对下标范围。
2. 每次入队按满条件判断，成功时先存值再令rear=(rear+1)%M。
3. 每次出队按空条件判断，成功时先取值再令front=(front+1)%M。
4. 用(rear−front+M)%M核对长度，并从front逐个回绕列出有效元素。

**公式与适用条件**

| 项目 | 公式或结论 | 适用条件 |
|---|---|---|
| 队空 | Q.front==Q.rear | 预留一个空位，front为队头位置，rear为下一写入位置。 |
| 队满 | (Q.rear+1)%M==Q.front | 数组容量M≥2，最大有效长度M−1。 |
| 队长 | (Q.rear−Q.front+M)%M | 0≤front,rear<M，采用本节空满约定。 |

**易错点**

- rear==M−1不等于队满，必须计算rear循环下一位置是否追上front。
- 直接用rear−front可能为负，必须先加M再取模。
- 循环队列公式中的front、rear是数组下标；不能当作顺序栈top、base的指针差。

### 例题：跨数组尾部的连续操作

**题目：**M=6，front=4，rear=1，初始data[4]=11、data[5]=22、data[0]=33。依次出队、入44、入55、入66、尝试入77，求输出与最终状态。

1. 初始长度(1−4+6)%6=3，逻辑序列(11,22,33)。
2. 出队得11，front由4变5，rear仍1。
3. 入44、55、66分别写下标1、2、3，rear依次变2、3、4。
4. 此时(rear+1)%6=5==front，入77失败且状态不变。
5. 从front=5回绕到rear=4之前，得到(22,33,44,55,66)。

**结论：**出队值11；最终front=5、rear=4、长度5，队列(22,33,44,55,66)已满，77未入队。

**教材来源：**3.5.2 顺序队的表示和实现，算法3.11—3.15；印刷页78–81（PDF第90–93页）。

**范围依据：**范围依据明确强调循环队列判空，并纠正纪要的混淆；按教材3.5.2预留一个空位方案，不能混用计数器或标志位方案。

### 重构类C示例（C指针接口，非教材源码逐字转写）

```c
enum { M = 6 };
typedef struct { int data[M]; int front, rear; } SqQueue;
/* 初始化front=rear=0；有效下标0..M-1，预留一个空位。 */
int QueueLength(const SqQueue *Q) {
    return (Q->rear - Q->front + M) % M;
}
int EnQueue(SqQueue *Q, int e) {
    if (!Q || (Q->rear + 1) % M == Q->front) return 0;
    Q->data[Q->rear] = e;
    Q->rear = (Q->rear + 1) % M;
    return 1;
}
int DeQueue(SqQueue *Q, int *out) {
    if (!Q || !out || Q->front == Q->rear) return 0;
    *out = Q->data[Q->front];
    Q->front = (Q->front + 1) % M;
    return 1;
}
```

- 此例固定M=6，可推广至任意M≥2；数组是重构的固定存储，教材使用base指针。
- 调用前0≤front,rear<M且状态满足预留空位约定；QueueLength要求Q有效，出队out与队列存储不重叠。
- 空队不读data[front]；满队不写data[rear]；失败保持状态与输出不变。

## 无头结点链栈的压入与弹出

**复习层级：** foundation；**依据：** suggestion。

这里采用教材不带头结点的链栈，栈顶指针S直接指向第一个数据结点。空栈用S==NULL表示，不能把带头结点单链表的L->next==NULL原样搬来。压入一个新结点时，先让它指向原S，再更新S；弹出时保存原栈顶结点及其后继，移动S后释放旧结点。两种操作都只在链首进行，不需要沿链查找尾部，逻辑上仍严格遵循后进先出。

**核心概念**

- **表示与结点所有权：**每个结点包含数据域与next，S拥有整条未弹出数据链的入口。一次成功压入新增一个结点，一次成功弹出释放一个结点，不能释放仍在链内的后继结点。
- **动态空间边界：**链栈没有预设数组容量，但申请内存仍可能失败，因此“链栈永不溢出”不严谨；失败压入应保持原S不变，不产生半接入结点。
- **C接口含义：**若在函数内修改调用者的栈顶变量，重构C接口使用LinkStack *S；*S才是实际栈顶。教材的引用参数写法与此等效表达修改意图，但语法不能混用。

**操作步骤**

1. 初始化实际栈顶变量为NULL，并将其地址交给需要改顶的函数。
2. 压入先申请p，失败则返回；成功后写数据、p->next=*S、*S=p。
3. 弹出先检查*S非空，保存p=*S及p->data，再令*S=p->next。
4. 最后free(p)，保证不在释放后再读p->next；空栈失败不改输出。

**公式与适用条件**

| 项目 | 公式或结论 | 适用条件 |
|---|---|---|
| 空链栈与操作代价 | S==NULL；单次Push/Pop为O(1) | 无头结点表示；不计内存分配器内部实现的变化成本。 |

**易错点**

- S是栈顶指针时S==NULL判空；在C二级指针函数里应检查的是*S，不能混淆这两个层次。
- free(p)之后再读取p->next属于使用已释放存储，应先更新栈顶。
- 同样叫单链结构，带头结点线性表与无头结点链栈的空状态不同。

### 例题：链栈由非空恢复为空

**题目：**初始S=NULL，依次压入4、压入8、弹出、弹出、再弹出一次。最后一次弹出前输出变量out设为99，失败不改out。

1. 入4后S指向4，4->next=NULL。
2. 入8后链为8→4→NULL，栈顶是8。
3. 首次弹出8并释放其结点，S改指向4；第二次弹出4并释放，S=NULL。
4. 第三次检测到空栈，返回失败，不释放任何结点，out仍为99。

**结论：**两次成功输出8、4；最终S=NULL，第三次失败且out=99。

**教材来源：**3.3.3 链栈的表示和实现，算法3.5—3.8；印刷页68–69（PDF第80–81页）。

**范围依据：**纪要强调栈操作但未单独锁定链栈代码；链栈按教材作为实现补充与比较训练，不提升为明确命题。

### 重构类C示例（C指针接口，非教材源码逐字转写）

```c
#include <stdlib.h>
typedef struct StackNode { int data; struct StackNode *next; } StackNode, *LinkStack;
int LinkPush(LinkStack *S, int e) {
    if (!S) return 0;
    StackNode *p = malloc(sizeof *p);
    if (!p) return 0;
    p->data = e;
    p->next = *S;
    *S = p;
    return 1;
}
int LinkPop(LinkStack *S, int *out) {
    if (!S || !out || !*S) return 0;
    StackNode *p = *S;
    *out = p->data;
    *S = p->next;
    free(p);
    return 1;
}
```

- 代码含标准头文件，采用无头结点表示；调用者先声明LinkStack top=NULL。
- LinkPush参数是&top；LinkPop的out为独立可写int对象，不与结点或top变量重叠。
- 压入失败不改top；调用者使用结束后须弹出并释放所有剩余结点。

## 带头结点链队及最后一个元素的删除

**复习层级：** foundation；**依据：** suggestion。

本节采用带头结点的链队。front始终指向头结点，真正的队头数据结点是front->next；rear指向最后一个数据结点，空队时rear也指向头结点。入队把新结点接在rear之后再更新rear，出队删除front后面的首个数据结点。由于头结点本身始终保留，front不必沿数据链移动；删去最后一个数据结点时必须把rear复位到front，避免留下指向已释放结点的悬空指针。

**核心概念**

- **初始化和空队：**分配一个头结点h，令h->next=NULL，front=rear=h。front==rear是此表示的空条件；与循环队列虽然公式表面相似，但这里比较的是结点指针而非数组下标。
- **入队与出队：**入队先令p->next=NULL，再rear->next=p、rear=p。出队令p=front->next，保存数据后front->next=p->next；若p==rear，再置rear=front，最后释放p。
- **复杂度和内存：**保留头、尾指针后单次入队与出队均为O(1)。动态分配仍可能失败；空队虽然没有数据元素，仍占一个头结点的空间，销毁时也要释放它。

**操作步骤**

1. 确认队列已初始化，front有效且rear指向当前尾结点或空队头结点。
2. 入队前申请新结点，成功后接到rear并更新rear，失败不改队列。
3. 出队先判front==rear，非空才取得front->next并保存数据。
4. 先接回后继，若删的是尾结点则rear=front，再释放旧队头；用下一次入队检验空态是否完整。

**公式与适用条件**

| 项目 | 公式或结论 | 适用条件 |
|---|---|---|
| 空链队 | Q.front==Q.rear，且头结点next为NULL | 带头结点且维护尾指针的链队，不使用模运算。 |

**易错点**

- 不能把front当作第一个数据结点读取data，头结点数据域不属于队列。
- 删最后一项却忘记重置rear，下一次入队可能写入已释放内存。
- 不带头结点链队会有另一组空指针维护规则，本节代码和结论不直接套用。

### 例题：删空后再次入队

**题目：**初始化只有头结点H，先入队5，再出队，最后入队8。逐步给出front、rear及数据链。

1. 初始front=rear=H，H->next=NULL。
2. 入5后front仍H，H->next指向结点5，rear指向5。
3. 出5时H->next置NULL，检测rear等于被删结点，将rear=H后释放5。
4. 再入8可安全通过H->next接入，front仍H，rear指向8。

**结论：**出队值5；最终front指向H，rear指向结点8，数据序列为(8)。

**教材来源：**3.5.3 链队的表示和实现，算法3.16—3.19；印刷页81–83（PDF第93–95页）。

**范围依据：**纪要强调队列入队出队；链式实现与删空维护按教材补充，用来防止与循环队列及链栈混淆，不声称已确定考此代码。

### 重构类C示例（C指针接口，非教材源码逐字转写）

```c
#include <stdlib.h>
typedef struct QNode { int data; struct QNode *next; } QNode;
typedef struct { QNode *front, *rear; } LinkQueue;
int InitLinkQueue(LinkQueue *Q) {
    if (!Q) return 0;
    QNode *h = malloc(sizeof *h);
    if (!h) return 0;
    h->next = NULL;
    Q->front = Q->rear = h;
    return 1;
}
int LinkEnQueue(LinkQueue *Q, int e) {
    if (!Q || !Q->front || !Q->rear) return 0;
    QNode *p = malloc(sizeof *p);
    if (!p) return 0;
    p->data = e;
    p->next = NULL;
    Q->rear->next = p;
    Q->rear = p;
    return 1;
}
int LinkDeQueue(LinkQueue *Q, int *out) {
    if (!Q || !out || !Q->front || Q->front == Q->rear) return 0;
    QNode *p = Q->front->next;
    *out = p->data;
    Q->front->next = p->next;
    if (Q->rear == p) Q->rear = Q->front;
    free(p);
    return 1;
}
```

- 调用InitLinkQueue前Q指向可写结构且不拥有已初始化活队列，避免重复初始化丢失原链。
- 后续操作要求链结构正确、front与rear均已初始化；out与队列及结点不重叠。
- 成功出队仅释放数据结点；整队使用结束还应释放剩余结点及保留的头结点。
