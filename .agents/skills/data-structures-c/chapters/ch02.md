## 顺序表表示、位序与地址计算

**复习层级：** focus；**依据：** explicit。

线性表是具有相同特性的数据元素的有限序列，长度可以为零；非空线性表的元素具有先后关系。顺序表利用一段连续空间存放线性表。教材中的逻辑位序从1开始，而C数组下标从0开始，因此第i个元素存于elem[i−1]。计算地址时应先统一基地址所对应的元素，再乘每个元素占用的存储单元数。顺序访问与随机存取不是同一个概念，随机存取说明按给定位序定位可为常数时间。

**核心概念**

- **长度与容量：**长度n是当前有效元素个数，容量是已分配空间能容纳的最大元素数，两者不能混用。访问要求1≤i≤n，插入另允许i=n+1。
- **位序与下标：**a1、a2等表示逻辑位序，elem[0]、elem[1]等表示实现下标。题目若另给任意下界，必须减去相应下界，而不是机械地减1。
- **地址单位：**若基地址B以字节计、每元素w字节，则偏移也按字节计算。题目会明确元素大小，不能根据int或指针名称自行假定平台字节数。

**操作步骤**

1. 写出B对应的是a1还是其他下标处的元素，并记录单位。
2. 将目标位序转换为相对于基元素的偏移个数。
3. 用偏移个数乘单个元素大小，再加基地址。
4. 检查位序是否落在有效元素范围；空表没有可取的第一个数据元素。

**公式与适用条件**

| 项目 | 公式或结论 | 适用条件 |
|---|---|---|
| 按逻辑位序寻址 | LOC(ai)=LOC(a1)+(i−1)×w | 1≤i≤n，元素等长且连续存储。 |
| 一般数组下标寻址 | LOC(A[k])=B+(k−b)×w | B=LOC(A[b])，k在合法范围内；地址和w单位一致。 |

**易错点**

- 把第i个元素直接当作elem[i]会使结果多偏移一个元素。
- 容量内尚未使用的单元不是当前线性表的有效元素，不能因地址可算就宣称取值合法。
- 顺序表可以按关键字无序；“顺序”描述连续存储而非数值排序。

### 例题：同时核对位序与地址

**题目：**顺序表有5个有效元素，a1的起始地址为1000，每元素8字节，求a4地址及其数组下标。

1. a4与a1相隔4−1=3个元素。
2. 偏移为3×8=24字节，地址为1000+24=1024。
3. a4对应elem[3]；位序4在1至5内，访问合法。
4. 若改问a6，虽然能算出存储偏移，也不属于该表当前有效元素。

**结论：**a4起始地址1024，对应下标3。

## 顺序表取值与按值查找

**复习层级：** focus；**依据：** explicit。

顺序表取值与按值查找回答不同问题。给定位序取值，可通过elem[i−1]直接取得元素，时间为O(1)；给定一个值寻找位置，在未排序的表中通常需要逐个比较，最坏时间为O(n)。本节遵循教材算法2.3的返回约定：从表头向后查找，成功返回第一个相等元素的1起始位序，失败返回0。这样位序1和失败0不会冲突，也便于分析重复值与空表。

**核心概念**

- **首次命中：**顺序查找从下标0开始，一旦发现相等就返回j+1。因此有重复关键字时返回最靠前的命中位置，不是所有位置，也不是最后一个位置。
- **成功与失败的代价：**在第i个位序命中需要i次元素比较；长度n的表查找失败需要n次比较。这里数元素相等比较，不把循环条件也算作一次关键字比较。
- **平均查找长度：**若n≥1且成功命中每个位序的概率均为1/n，成功平均比较次数为(n+1)/2；如果给了失败概率或非均匀概率，应按题设重新加权。

**操作步骤**

1. 先确认输入是位序还是目标值，避免把取值复杂度套给查找。
2. 从下标0比较到length−1，首次相等返回下标加1。
3. 循环结束仍未命中，返回0；空表循环不执行也返回0。
4. 按命中位序或失败情况统计比较次数，再在明确的概率模型下求平均。

**公式与适用条件**

| 项目 | 公式或结论 | 适用条件 |
|---|---|---|
| 成功平均比较次数 | ASL=(1+2+…+n)/n=(n+1)/2 | n≥1，目标必然存在且每个位序等概率。 |
| 失败比较次数 | Cfail=n | 逐个扫描全部n个元素，不使用哨兵。 |

**易错点**

- 返回j会把首元素命中返回成0，与教材失败标记冲突。
- 数组支持随机存取，不表示在无序表中按值查找也只需O(1)。
- 没有给成功概率时，不能把失败的n次比较混入等概率成功平均公式。

### 例题：重复关键字和失败情形

**题目：**L=(18,7,18,25)。依次独立查找18和9，返回什么位序，各比较几次？

1. 查找18时，第1个元素已经相等，立即返回1，只比较1次。
2. 查找9时依次比较18、7、18、25，均不相等。
3. 全部4个元素比较完毕返回0，不能返回最后检查的下标。
4. 若L为空，两次查找都返回0，元素比较次数为0。

**结论：**查18：返回1、比较1次；查9：返回0、比较4次。

**教材来源：**2.4.2 顺序表中基本操作的实现，算法2.2—2.3；印刷页26–27（PDF第38–39页）。

```c
typedef struct { int elem[100]; int length; } SqList;
int LocateElem(const SqList *L, int e) {
    for (int j = 0; j < L->length; ++j)
        if (L->elem[j] == e) return j + 1;
    return 0;
}
```

## 顺序表插入、删除与移动次数

**复习层级：** focus；**依据：** explicit。

在长度为n的顺序表第i个位序插入，含义是在原第i个元素之前放入新值；允许1≤i≤n+1，且必须留有容量。由于逻辑顺序要保持，插入时应从后向前把原元素整体右移，避免覆盖尚未搬走的数据。删除第i个元素则要求1≤i≤n，先保存被删值，再把其后的元素从前向后左移。两种操作均在成功后恰好修改一次长度，非法请求应保持表及输出参数不变。

**核心概念**

- **插入移动范围：**原数组下标从n−1递减到i−1，赋值elem[j+1]=elem[j]。写入位置为elem[i−1]；空表只允许位序1，尾插不移动已有元素。
- **删除移动范围：**保存elem[i−1]后，从下标i递增到n−1，赋值elem[j−1]=elem[j]。删除末元素无须移动；空表没有合法删除位序。
- **复杂度与概率：**最坏插入和删除均为O(n)，尾部可为O(1)。等概率选择n+1个插入位置时平均移动n/2个；等概率删除n个元素时平均移动(n−1)/2个。

**操作步骤**

1. 先核对当前长度、容量和位序，不合法立即失败且不修改状态。
2. 插入采用从后向前右移，删除采用从前向后左移，写明首末下标。
3. 写入新值或保存被删值，再在成功路径更新length。
4. 用操作前的长度计算本次移动次数；连续多次操作必须先更新长度再算下一步。

**公式与适用条件**

| 项目 | 公式或结论 | 适用条件 |
|---|---|---|
| 插入移动数 | n−i+1 | 在原第i个元素前插入，1≤i≤n+1，空间足够。 |
| 删除移动数 | n−i | 删除操作前长度为n，1≤i≤n。 |
| 等概率平均移动数 | 插入n/2；删除(n−1)/2 | 分别在全部合法插入或删除位序上等概率，删除要求n≥1。 |

**易错点**

- 插入时从前向后移动会覆盖后续原值；不能照搬删除方向。
- 先增加length再用新长度当作原长度，会访问错误的边界单元。
- 满表即使尾插也失败；移动次数为0不等于无需检查容量。

### 例题：连续插入与删除

**题目：**L=(10,20,30,40,50)，容量至少6。先在位序2插入15，再删除新表位序5，给出各次移动次数及最终表。

1. 插入前n=5，右移原下标4、3、2、1，共5−2+1=4个元素。
2. 写入elem[1]=15，得到(10,15,20,30,40,50)，长度6。
3. 新表位序5是40；删除时只需把50左移，共6−5=1个。
4. 长度减为5，得到(10,15,20,30,50)。

**结论：**插入移动4个，删除移动1个、删值40；最终(10,15,20,30,50)。

**教材来源：**2.4.2 顺序表的插入与删除，算法2.4—2.5；印刷页27–29（PDF第39–41页）。

### 重构类C示例（C指针接口，非教材源码逐字转写）

```c
typedef struct { int elem[100]; int length; } SqList;
int ListInsert(SqList *L, int i, int e) {
    if (!L || i < 1 || i > L->length + 1) return 0;
    if (L->length == 100) return 0;
    for (int j = L->length - 1; j >= i - 1; --j)
        L->elem[j + 1] = L->elem[j];
    L->elem[i - 1] = e;
    ++L->length;
    return 1;
}
int ListDelete(SqList *L, int i, int *out) {
    if (!L || !out || i < 1 || i > L->length) return 0;
    *out = L->elem[i - 1];
    for (int j = i; j < L->length; ++j)
        L->elem[j - 1] = L->elem[j];
    --L->length;
    return 1;
}
```

- 使用固定数组SqList，容量100，1起始位序；调用前须满足0≤length≤100。
- 输出out必须是独立有效int对象，不与表的内部存储重叠；失败时不写out。
- 用C指针参数替代教材引用参数，新增参数检查与删除值输出，不是教材源码原样转写。

## 带头结点单链表与头插法

**复习层级：** focus；**依据：** explicit。

本知识点统一采用带头结点的非循环单链表：L指向头结点，头结点不作为有效数据元素计数，首元结点由L->next指向，尾结点的next为NULL。头插法每次把新结点接在头结点之后，故按某顺序读入数据后，最终数据次序与读入次序相反。头插的核心不在申请结点，而在正确保存原首元链，再让头结点指向新结点；交换这两条接链语句可能制造自环并丢失原链。

**核心概念**

- **三个“头”的区别：**头指针是指针变量，头结点是附加结点，首元结点保存第一个有效元素；它们不是同一概念。初始化后空表L不为NULL，而L->next为NULL。
- **头插不变式：**处理完前k个输入后，头结点后的链恰为这k个输入的逆序，每个结点都可从L到达，最后一个结点next为NULL。
- **局部插入与整体建表：**已知头结点时插入一个新结点只改常数个指针，时间O(1)；连续插入n个输入建表时间O(n)，新增n个数据结点另加一个头结点。

**操作步骤**

1. 建立或确认有效头结点，并令空表L->next=NULL。
2. 申请新结点p、检查分配结果，再写入数据域。
3. 先执行p->next=L->next保存原首元链，再执行L->next=p完成接入。
4. 处理下一个输入；模拟时每步都从L->next重画实际逻辑顺序。

**公式与适用条件**

| 项目 | 公式或结论 | 适用条件 |
|---|---|---|
| 头插建表的次序 | 输入a1,a2,…,an，结果an,…,a2,a1 | 每次插在同一头结点之后，n可为0。 |

**易错点**

- 带头结点的空表不是L==NULL；L==NULL通常说明头结点尚未建立。
- 先写L->next=p，再写p->next=L->next，会让p指向自身。
- 不能把一次局部接链O(1)说成按位序查找前驱也O(1)；寻找结点通常还要遍历。

### 例题：逐次头插并检验指针顺序

**题目：**对空的带头结点单链表依次输入3、5、7并头插，求最终序列；若先写L->next=p再写p->next=L->next会怎样？

1. 初始L->next=NULL。插入3后，链为头→3→NULL。
2. 插入5时先让5指向原3，再让头指向5，链为头→5→3→NULL。
3. 插入7后为头→7→5→3→NULL，逆于输入顺序。
4. 错误写法中第二句读到的L->next已经是p，故p->next=p形成自环，原链失去头指针入口。

**结论：**正确结果(7,5,3)；交换两句会造成新结点自环并丢失原首元链的入口。

**教材来源：**2.5.1 单链表的定义和表示；2.5.2 前插法创建单链表，算法2.11；印刷页30–37（PDF第42–49页）。

**范围依据：**范围依据第二章明确列出顺序表查找、插入、地址计算及单链表头插、尾插和代码；这里据此安排训练，不承诺具体命题或分值。

### 重构类C示例（C指针接口，非教材源码逐字转写）

```c
#include <stdlib.h>
typedef struct LNode { int data; struct LNode *next; } LNode, *LinkList;
int PushFront(LinkList L, int e) {
    if (!L) return 0;
    LNode *p = malloc(sizeof *p);
    if (!p) return 0;
    p->data = e;
    p->next = L->next;
    L->next = p;
    return 1;
}
```

- L必须是已分配的头结点，头结点数据域不计入线性表；调用前链表无环且next有效。
- 函数每成功调用一次完成一次头插；n=0时不调用即可保持空表。
- malloc失败返回0且原链不变；调用者负责最终释放全部数据结点和头结点。

## 尾插法、前驱操作与存储取舍

**复习层级：** focus；**依据：** explicit。

尾插法用尾指针r保持最后一个结点的位置，每读入一个新值，就把新结点接在r之后并更新r。带头结点的空表将r初始化为L，可使第一个数据结点与后续结点采用同样的接链步骤。尾插保留输入顺序；若每插一个结点都从头重新寻找表尾，整个建表会从O(n)退化到O(n²)。链表插删是否高效，也取决于是否已经得到所需前驱，不能只看最终改了几条指针。

**核心概念**

- **尾插不变式：**每轮结束后，r指向最后一个数据结点；尚未插入任何数据时r=L。始终维持r->next=NULL，从L可遍历到已读入的全部元素，次序与输入一致。
- **按前驱删除：**带头结点单链表删除某结点q时，先找到其前驱p，再令p->next=q->next，最后释放q。先释放后读取q->next是访问已释放存储。
- **顺序表与链表比较：**顺序表按位序取值方便但中间插删要移动；链表无需整体搬移却有指针开销，按位序定位仍需遍历。循环、双向等变体会改变表示和操作条件，不能套用本节全部结论。

**操作步骤**

1. 建立头结点令L->next=NULL，并置r=L。
2. 为输入值建立p，先令p->next=NULL，保证其可作为新尾结点。
3. 依次执行r->next=p、r=p，维持尾指针不变式。
4. 建表失败时释放本次已建结点；处理删除时先保存后继再释放原结点，并检查是否另有持久尾指针需更新。

**公式与适用条件**

| 项目 | 公式或结论 | 适用条件 |
|---|---|---|
| 建表时间 | 维护尾指针时O(n)；每次遍历找尾时Σ(k=0..n−1)k=O(n²) | 对n个元素逐个尾插，不把输入读取的外部成本另行放大。 |

**易错点**

- 忘记r=p会使下一次插入覆盖原尾的后继，导致部分链丢失。
- 尾插不是往数组高地址写入，结点实际地址可以不连续。
- 这里建表局部变量r在函数结束后不保留；若另设计含尾指针的表结构，删除尾结点必须同步更新它。

### 例题：尾插建表后删除首个匹配值

**题目：**尾插输入(4,9,4)，然后删除首个值为4的结点。说明构造次序与删除指针变化。

1. 初始r=L。插入4后r指向首个4；再插9与末个4，链为头→4→9→4→NULL。
2. 删除时从头结点找前驱p=L，q=p->next即首个4。
3. 先令p->next=q->next使头直接连到9，再释放q。
4. 剩余链为头→9→4→NULL，末个4保留；空表或无匹配值应报告未找到且不改链。

**结论：**尾插保持(4,9,4)，删除首个匹配后为(9,4)，不能把两个4都删除。
